BOOST Plugin Algorithm Context
========================================

## Feature Groups

### TDD-based ISF (gate: boost_use_tdd)
Core Boost engine: computes dynamic ISF from total daily dose (TDD) using 7D/24H/8H/4H weighted blends. Uses ln(bg/divisor+1)*1800/TDD formula. Includes circadian ISF, DynISF velocity scaling, and sensitivity adjustment.
Key parameters: boost_adjust_sensitivity, boost_autosens_when_no_tdd, boost_percent_scale_factor, boost_scale_value, boost_use_tdd, enableBoostPercentScale

### Meal Model (V5/V6/V7) (gate: None)
Multi-version meal hypothesis system. V5: aggression/hypo-caution scaling. V6: pre-meal target, lead time, committed/confirmed cap thresholds. V7: residual pools. Anticipation history for meal-time learning.
Key parameters: boost_anticip_history, boost_meal_time_history, boost_v5_active_dosing, boost_v5_aggression, boost_v5_aggressive_early_confirm, boost_v5_autoconfig_done, boost_v5_committed_cap_u, boost_v5_composed_floor_active, boost_v5_confirmed_cap_u, boost_v5_fast_carb_confirm

### Activity & Steps (gate: boost_activity_shadow_enabled)
Step counting from Wear OS / Health Connect / phone sensors. Activity % and inactivity % scale ISF. Activity shadow mode computes but doesn't apply. Post-exercise recovery with configurable duration/scale.
Key parameters: boost_activity_pct, boost_activity_shadow_enabled, boost_activity_steps_15, boost_activity_steps_30, boost_activity_steps_5, boost_activity_steps_60, boost_daily_step_history, boost_inactivity_pct, boost_inactivity_steps, boost_intraday_step_bank

### Night Mode (gate: boost_night_mode_enabled)
Reduces insulin during configured night window. Auto-by-sleep option. COB and low-TT disable gates. BG offset for tighter overnight control.
Key parameters: boost_night_mode_auto_by_sleep, boost_night_mode_bg_offset, boost_night_mode_disable_with_cob, boost_night_mode_disable_with_low_tt, boost_night_mode_enabled, boost_night_mode_end, boost_night_mode_start

### Sleep Detection (gate: None)
Tracks sleep state from steps/inactivity patterns. Sleep-in hours/steps thresholds. Hysteresis for wake/sleep transitions. Pre-sleep lead time.
Key parameters: boost_pre_sleep_lead_min, boost_sleep_history, boost_sleep_hysteresis_min, boost_sleep_in_hrs, boost_sleep_state, boost_wake_hr_hysteresis_min

### HR Stress Detection (gate: boost_health_connect_hr_enabled)
Health Connect heart rate integration. Detects stress from elevated resting HR. Configurable max/resting BPM, window minutes, polling interval.
Key parameters: boost_health_connect_hr_enabled, boost_health_connect_poll_min, boost_hr_integration_enabled, boost_hr_max_bpm, boost_hr_resting_bpm, boost_hr_stress_detection, boost_hr_window_minutes

### Post-Exercise Recovery (gate: boost_post_exercise_recovery_enabled)
Recovery window after exercise ends. Configurable hours, scale factor, minimum duration gate, and recovery target BG.
Key parameters: boost_post_exercise_min_duration, boost_post_exercise_recovery_enabled, boost_post_exercise_recovery_hours, boost_post_exercise_recovery_scale, boost_post_exercise_recovery_target

### SMB Delivery (gate: openapsama_use_smb)
Boost SMB delivery controls: cumulative 60-min cap, bolus size, max IOB, insulin requirement %. Interacts with standard SMB settings (frequency, basal-to-limit, UAM limits).
Key parameters: boost_bolus_cap, boost_cumulative_smb_cap_60min, boost_insulin_req_pct, boost_max_iob, enableSMB_after_carbs, enableSMB_always, enableSMB_with_COB, enableSMB_with_high_temptarget, enableSMB_with_temptarget, openapsmb_max_iob

### ML Feature Ring Buffer (gate: None)
6-position lookback ring buffer for ML features. Stores recent-SMB stats, BG trends. Serialized per cycle to persistence.
Key parameters: boost_ml_ring_buffer

### ISF Shadow (V4.4.2-style EMA) (gate: None)
Parallel EMA(τ=3h) sensitivity ratio computed alongside real ISF. Does NOT influence dosing — diagnostic only. Shadow state persisted.
Key parameters: boost_isf_shadow_state

### Shared AAPS Settings (gate: None)
Standard OpenAPS settings that Boost's algorithm also reads: max basal, max IOB, SMB gates, autosens, dynamic sensitivity.
Key parameters: DynISFAdjust, autosens_max, autosens_min, boost_allow_all_bg_sources, boost_dynisf_bg_cap, boost_dynisf_normal_target, boost_dynisf_velocity, carbsReqThreshold, enableBoost_with_high_temptarget, enableCircadianISF

### Safety (gate: None)
Ketoacidosis protection, force limits, half-basal exercise target.


## Key Parameters

### DynISFAdjust
Type: Int, Default: 100
Summary: Percentage factor for the global dynamic ISF strength; 100 = standard, higher = more dynamic adjustment.
High: Higher value — more insulin/greater effect
Low: Lower value — less insulin/reduced effect
Impact: medium | Feature: shared_aaps

### autosens_max
Type: Double, Default: 1.2
Range: 0.5 – 3.0
Summary: Default value: 1.2\nThis is a multiplier cap for autosens (and deviation sensitivity) to set how high the sensitivity ratio can go, which determines how far ISF can be lowered during resistant periods.
High: Allows larger autosens sensitivity ratio = less insulin when sensitive
Low: Limits sensitivity ratio = less reduction, more stable
Impact: high | Feature: shared_aaps

### autosens_min
Type: Double, Default: 0.7
Range: 0.1 – 1.0
Summary: Default value: 0.7\nThis is a floor for autosens (and deviation sensitivity) to set how low the sensitivity ratio can go, which determines how far ISF can be raised during sensitive periods.
High: Lower minimum = allows stronger ISF reduction when resistant
Low: Higher minimum = less aggressive resistance response
Impact: high | Feature: shared_aaps

### boost_activity_pct
Type: Double, Default: 80.0
Range: 30.0 – 150.0
Summary: Profile percentage to use when activity is detected (high steps); &lt;100 means reduce basal during exercise.
High: More ISF during activity = less insulin = safer
Low: Less ISF during activity = more insulin = hypo risk
Impact: high | Feature: activity

### openapsama_current_basal_safety_multiplier
Type: Double, Default: 4.0
Range: 1.0 – 10.0
Summary: Default value: 4 This is the other half of the key OpenAPS safety caps, and the other half of “3x max daily; 4x current” of the safety caps. This means your basal, regardless of max basal set on your pump, cannot be any higher than this number times the current level of your basal. This is to prevent people from getting into dangerous territory by setting excessively high max basals before understanding how the algorithm works. Again, the default is 4x; most people will never need to adjust this and are instead more likely to need to adjust other settings if they feel like they are “running into” this safety cap.
High: Higher value — more insulin/greater effect
Low: Lower value — less insulin/reduced effect
Impact: critical | Feature: shared_aaps
