> Apply the same method to any plugin.

## Goal

Read the AIMI Kotlin source code and update `analyzer/data/aimi_parameters.json`
with accurate, English descriptions for every active parameter:
- `logic_summary` — what the parameter does in one sentence
- `effect_high` — what happens at high values
- `effect_low` — what happens at low values
- `impact` — critical / high / medium / low
- `used_in` — which functions use it and how

This is the **human understanding layer** — it cannot be generated by a script.
Claude must actually read and understand the Kotlin code.

## Process

### Step 1: Load existing parameters

```python
import json
with open('analyzer/data/aimi_parameters.json') as f:
    data = json.load(f)
params = data['parameters']
# Focus on active, non-orphaned parameters
active = [p for p in params if not p.get('orphaned')]
print(f"Parameters to enrich: {len(active)}")
```

### Step 2: For each parameter, find its usage in source

For each parameter key (e.g. `key_openapsaimi_max_smb`):

1. Find the enum entry in the Key files → get the variable name (e.g. `OApsAIMIMaxSMB`)
2. Search for `preferences.get(DoubleKey.OApsAIMIMaxSMB)` in all source files
3. Read the surrounding code (±30 lines) to understand what it does
4. Write `logic_summary`, `effect_high`, `effect_low` in plain English

```bash
# Example search:
grep -n "OApsAIMIMaxSMB\|key_openapsaimi_max_smb" \
  plugins/aps/src/main/kotlin/app/aaps/plugins/aps/openAPSAIMI/DetermineBasalAIMI2.kt
```

### Step 3: Determine impact

Use this criteria:

| Impact | Criteria |
|--------|----------|
| `critical` | Directly controls max insulin delivery, safety limits, or feature on/off |
| `high` | Significantly affects SMB size, ISF scaling, or correction aggressiveness |
| `medium` | Modulates timing, thresholds, or secondary adjustments |
| `low` | Fine-tuning, rarely changes outcome significantly |

### Step 4: Write enriched data back

```python
# Update a parameter
for p in params:
    if p['key'] == 'key_openapsaimi_max_smb':
        p['logic_summary'] = "Hard cap on SMB size per delivery tick."
        p['used_in'] = [{
            'function': 'determineBasalAdapterSMBJS',
            'usage_type': 'limit',
            'effect_high': "Allows larger SMBs — faster correction but higher stacking risk",
            'effect_low': "Restricts SMB size — safer but slower correction of highs"
        }]
        p['impact'] = 'critical'
        break

# Save
with open('analyzer/data/aimi_parameters.json', 'w') as f:
    json.dump(data, f, indent=2, ensure_ascii=False)
```

### Step 5: Update aimi_context_for_ai.json

Also update `parameter_knowledge` entries in `aimi_context_for_ai.json` for the
most important parameters (critical + high impact):

```python
with open('analyzer/data/aimi_context_for_ai.json') as f:
    ctx = json.load(f)

# Rebuild parameter_knowledge from enriched params
ctx['parameter_knowledge'] = [
    {
        'key': p['key'],
        'name': p['name'],
        'logic_summary': p.get('logic_summary', ''),
        'effect_high': (p.get('used_in') or [{}])[0].get('effect_high', ''),
        'effect_low': (p.get('used_in') or [{}])[0].get('effect_low', ''),
        'feature_group': p.get('feature_group', ''),
        'impact': p.get('impact', 'medium'),
        'settings_path': p.get('settings_path', ''),
    }
    for p in params
    if not p.get('orphaned') and p.get('logic_summary')
]

with open('analyzer/data/aimi_context_for_ai.json', 'w') as f:
    json.dump(ctx, f, indent=2, ensure_ascii=False)
```

## Parameter dependencies (gate suppression)

This is critical for correct AI recommendations. A parameter can be:

1. **`gate_key`** — parameter only exists/matters when a feature gate is ON
   Already extracted by `generate_data.py`. No action needed.

2. **`negative_gate_key`** — parameter is present and has a value, but has
   **NO effect** when a specific gate is ON (because that mode bypasses the
   code path that reads this parameter).

### Known verified cases (do NOT change these):

```python
# These 9 SMB params are suppressed when T3c Brittle Mode is active
# because executeT3cBrittleMode() bypasses all SMB logic
T3C_SUPPRESSED = {
    "key_openapsaimi_max_smb",
    "key_openapsaimi_high_bg_max_smb",
    "aimi_smb_tail_damping",
    "aimi_smb_tail_threshold",
    "aimi_smb_exercise_damping",
    "aimi_smb_late_fat_damping",
    "aimi_isf_fusion_min_factor",
    "aimi_isf_fusion_max_factor",
    "aimi_isf_fusion_max_change_per_tick",
}
# negative_gate_key = "key_aimi_t3c_brittle_mode"
```

### Find new suppression cases:

For each major feature gate, look for early-return or bypass patterns in the code:

```bash
# Example: find where T3c Brittle bypasses normal flow
grep -n "t3cBrittle\|T3cBrittle\|brittle_mode\|executeT3c" \
  plugins/aps/src/main/kotlin/app/aaps/plugins/aps/openAPSAIMI/DetermineBasalAIMI2.kt \
  | head -20

# Example: find where Autodrive V3 overrides normal SMB calculation
grep -n "autoDriveActive\|AutoDriveGater\|autoDrive.*return\|return.*autoDrive" \
  plugins/aps/src/main/kotlin/app/aaps/plugins/aps/openAPSAIMI/DetermineBasalAIMI2.kt \
  | head -20
```

### For each gate, verify suppression pattern:

Read the bypass function and list ALL `preferences.get()` calls that are
**skipped** when the gate activates. A parameter is suppressed if:
- The gate causes a `return` or early exit before the parameter is read, OR
- The gate causes the parameter's code branch to be completely skipped

```python
# How to set negative_gate_key:
for p in params:
    if p['key'] in T3C_SUPPRESSED:
        p['negative_gate_key'] = 'key_aimi_t3c_brittle_mode'
```

### Result in aimi_parameters.json:

```json
{
  "key": "key_openapsaimi_max_smb",
  "gate_key": null,
  "negative_gate_key": "key_aimi_t3c_brittle_mode",
  "logic_summary": "Hard cap on SMB size per delivery tick.",
  "impact": "critical"
}
```

The analyzer backend uses `negative_gate_key` to:
1. Filter these params out of AI recommendations when the negative gate is active
2. Show a warning: "Suppressed by T3c Brittle Mode — parameter has no effect"
3. Exclude them from the active parameters block in the AI prompt



- All text in **English only** — no German
- `logic_summary` max 2 sentences
- `effect_high` / `effect_low` max 1 sentence each
- Be specific: "increases SMB delivery by up to X%" not "makes it more aggressive"
- Reference the algorithm stage or function name when possible
- If a parameter is read but has no effect (orphaned logic), mark `orphaned: true`

## Validation after enrichment

```python
import re, json

with open('analyzer/data/aimi_parameters.json') as f:
    data = json.load(f)
params = data['parameters']

active = [p for p in params if not p.get('orphaned')]
with_summary = [p for p in active if p.get('logic_summary')]
with_effects = [p for p in active if p.get('used_in') and p['used_in'][0].get('effect_high')]

print(f"Active params:     {len(active)}")
print(f"With summary:      {len(with_summary)} ({len(with_summary)*100//len(active)}%)")
print(f"With effects:      {len(with_effects)} ({len(with_effects)*100//len(active)}%)")

# No German
german = [p['key'] for p in active if re.search(r'[äöüÄÖÜß]', json.dumps(p))]
print(f"German chars:      {len(german)} {'✅' if not german else '❌ ' + str(german[:5])}")

# Critical params all enriched
critical = [p for p in active if p.get('impact') == 'critical']
critical_no_summary = [p for p in critical if not p.get('logic_summary')]
print(f"Critical enriched: {len(critical)-len(critical_no_summary)}/{len(critical)}")
if critical_no_summary:
    print(f"  Missing: {[p['key'] for p in critical_no_summary]}")
```
